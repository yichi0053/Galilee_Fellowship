# ADR-0011：一律頂部導覽列，發文按鈕採 FAB

**Status**: Accepted

## Context

手機與桌機是否要兩套導覽？發文按鈕放哪裡？

## Decision

一律使用頂部導覽列，手機與桌機共用同一套結構。發文按鈕獨立為右下角的 FAB（Floating Action Button）。

## Consequences

**代價**：
- 牆頁頂部堆疊三層（導覽列、當週主題橫幅、週次選擇器），在手機上佔掉超過三分之一螢幕高度。
- 因此必須實作捲動收合：向下捲動時隱藏導覽列與主題橫幅，僅保留週次選擇器；向上捲動時復原。這是額外工時，且捲動事件處理容易在 iOS Safari 上出現抖動。

理由：兩套導覽等於兩套要維護的結構。發文為最高頻動作，放在頂部會嚴重犧牲拇指可觸及性，故獨立為 FAB。FAB 不屬於導覽列，與「一律頂部導覽」不衝突。

---

**2026-08-27 修訂**：原本三層一起 `sticky`、再依捲動方向收合上面兩層。
實際用起來週次 bar 會在畫面上不斷上下移動——往下捲時慢慢升到頂端，
稍微往上捲一點兩層就回來又把它推下去。改為**只有週次選擇器釘在頂端**，
導覽列與主題橫幅照常捲走。

代價：捲到牆面下方時看不到「我的貼文」等導覽連結，要回頂端才有。
牆一次只顯示一週（§10.6）所以頁面不長，這個代價可以接受。
換得的是少一個 scroll 監聽器——手機上每次捲動都要跑的東西。
