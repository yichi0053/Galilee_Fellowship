# ADR-0021：自行刪除改為 20 分鐘內限定，逾期不可刪

**Status**: Accepted（修訂 [ADR-0010](0010-quota-refund-window.md)）

## Context

ADR-0010 的規則有兩段：10 分鐘內刪除回補配額，逾期仍可刪但不回補。
卡片上因此出現一行「刪除可回補配額 09:12」。

問題是使用者得同時理解兩個概念——刪除，以及配額回補——而後者在畫面上只是一行小字，
在牆上滑過去的人不會停下來想「回補」是什麼意思。更麻煩的是逾期之後那行字變成
「回補期已過。現在刪除不會拿回這次的配額。」，講的是一件使用者本來就不知道存在的事。

## Decision

只留一段規則：**發布後 20 分鐘內可以自行刪除，逾期刪不掉。**

- 期限內刪除等同「撤回」：貼文消失，配額退還。不再有 `case` 判斷。
- 逾期後 `soft_delete_post` 直接 `raise exception`（migration 012）。
- 卡片上的字改為「還可刪除 19:32」，貼文頁逾期後直接移除刪除按鈕。
- 時間一律以伺服器的 `now()` 判定，前端的倒數只是畫面。

## Consequences

**代價**：

- **逾期後成員無法自行移除自己的照片。** 這是本決策最重的代價。
  §8.6 說成員名單帶有宗教信仰資訊、屬個資法第 6 條特種個人資料，
  而「拿不掉」與「要透過別人才拿得掉」是完全不同的兩件事。
  因此 `/join` 的告知同意第 3 點必須同步改寫並**指出事後的管道**
  （聯絡團契負責人下架），只寫前半句就是不實陳述。
  唯一的移除路徑變成管理員的 `admin_set_post_hidden`，而 ADR-0014 已載明
  單一管理員是已知的單點失效——這條路徑也因此繼承了那個風險。
- **20 分鐘比 10 分鐘更容易被拿來繞過配額。** 發文、看一眼牆上效果、刪掉重發，
  現在有兩倍的時間可以來回。24 人的信任模型（ADR-0005）下不值得為此加限制。
- **舊貼文一律刪不掉了。** migration 012 之後，所有超過 20 分鐘的既有貼文
  都只能由管理員下架。上線初期資料量小，不另寫過渡措施。
- **前端與資料庫各有一份 20 分鐘。** `DELETE_WINDOW_MINUTES` 與 migration 012 的
  `interval '20 minutes'`，兩邊不一致的失敗模式是「畫面說還有時間，按下去卻被拒絕」。

理由：一個概念、一個倒數，比兩個概念加一行小字好懂。
使用者要的是「我後悔了，撤回」，不是「我想了解配額的回補機制」。
