# ADR-0013：分期釋出功能作為維持參與度的手段

**Status**: Accepted

## Context

照片牆本質是 broadcast 媒介，典型失效模式為前兩週熱度高、第三週後發文量斷崖式下滑。

## Decision

第一期只做核心照片牆，其餘六期功能分散於第 3 至 18 週釋出。

## Consequences

**代價**：
- 使用者需經歷多次新功能說明，每次都有解釋成本與學習成本。
- 開發工作橫跨整個學期，無法一次做完收工。
- 每期功能都必須在既有 schema 上擴充，若第一期邊界劃錯，後續每期都要付利息。
- 功能開關（`config/features.ts`）需要維護，且未啟用的程式碼仍在 bundle 中。

理由：第五週推出新玩法，效果優於第一週塞滿功能然後八週無變化。分批釋出本身即為維持參與度的手段。
