# ADR-0020：上傳時可拖曳決定縮圖範圍，原圖完整保留

**Status**: Accepted

## Context

牆頁的卡片顯示縮圖。在此之前，縮圖的顯示範圍經歷過兩個版本，兩個都不理想：

1. **固定正方形加 `object-fit: cover`**（至 2026-08-27）。
   `--ratio` 從未被賦值，於是每張照片都被硬裁成正方形，直式手機照上下各切掉一截，
   而切在哪裡完全由瀏覽器決定。
2. **照片的自然比例**（2026-08-27 起）。不再裁切，但作者對「牆上看到什麼」沒有發言權——
   一張人在角落的合照，牆上就是一張以背景為主的照片。

兩者的共同問題是：**決定構圖的人不是拍照的人。**

## Decision

發文時在預覽圖上提供一個可拖曳、可拉角落改變大小的裁切框。

- **比例不限**，使用者自由拉。框的比例即卡片的比例，牆面因此保持高低錯落的 masonry 質感。
- **框在拖曳當下就夾在 0.62 至 1.5**（`clampCrop`），不是裁完再由 CSS 夾。
- **只作用於縮圖。** 主圖一律以完整構圖上傳，`/post/:id` 顯示全貌。
- 預設框：比例在範圍內的照片是「整張都要」，太長或太扁的則自動置中夾成合法的框。

## Consequences

**代價**：

- **發文流程多一個步驟。** 這是本專案最貴的一次互動實作——拖曳、觸控手勢、
  canvas 區域繪製、以及一個新元件。ADR-0007 當初否決自由拖曳排版正是因為這類成本。
  以「預設框已經是合理值、不動它也能發文」降低摩擦。
- **牆上與貼文頁看到的不是同一張構圖。** 點進去會看到框外的部分，
  對「這張照片就是我框的那樣」的期待是一種落差。換得的是原始構圖不會永久失去——
  第一期沒有編輯功能，裁錯只能刪掉重發，而刪掉重發要耗配額。
- **比例仍被夾住。** 使用者拉不出 9:16 的框。不夾的話一張卡片會獨佔整個欄位，
  兩欄的牆會變成一欄。這個限制在拖曳時就生效，所以是「拉不動」而不是「拉了沒用」。
- **舊貼文不受影響。** migration 011 之前的貼文縮圖是整張縮的，沒有補救路徑，
  也不值得為兩篇測試資料寫一支回填。

理由：照片牆的主角是照片，而照片的重點在哪裡只有拍的人知道。
